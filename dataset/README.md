# Dito 人格训练集

给模型做人格微调（SFT/LoRA）用的数据集，全部依据 `personas/dito.md`（最新版）手工编写，不是生成的占位内容。

## 目录

```
dataset/
├── system_prompt.txt        # 训练用 system prompt（从人设提炼，含 QQ 聊天 + 互联网知识要求）
├── data_chitchat.py         # 闲聊单轮 87 条
├── data_qq_chat.py          # QQ 聊天风格短句 40 条
├── data_internet.py         # 互联网/世界知识 135 条（二次元/F1/足球/世界/数理化）
├── data_refusal.py          # 边界与红线拒绝 37 条
├── data_professional.py     # 专业问题 42 条（Linux/开发/游戏兼容/推荐等）
├── data_multiturn.py        # 多轮对话 15 组 47 轮
├── build.py                 # 合并生成 dist/ 下的 JSONL
├── validate.py              # 风格硬规则校验（可直接接 CI）
└── dist/
    ├── dito_sft_chatml.jsonl   # OpenAI messages 格式（推荐）
    └── dito_sft_alpaca.jsonl   # alpaca 格式（多轮已拍平进 history）
```

## 构建

```bash
python3 build.py      # 生成 dist/*.jsonl
python3 validate.py   # 校验风格规则，非 0 退出码
```

## 风格硬规则（校验脚本自动卡）

| 规则 | 适用范围 |
|------|---------|
| 无 emoji（一个都不行） | 所有回复 |
| 无（戴上眼镜）类动作描写 | 所有回复 |
| 无 `**加粗**` | 所有回复 |
| ≤30 字、结尾不加句号、单行 | category=chitchat |
| 直接给结论、说明几成把握 | 专业类由人工保证 |

校验脚本只卡机器可判的规则，专业类内容的正确性（比如 pacman 命令、ProtonDB 结论）人工核对过。

## 设计决策

1. **红绿灯用文字不用符号**：旧版人设（`dito-蒂特 (副本).md`）里 AUR 审查和游戏兼容性用 🟢🟡🔴，跟"绝对不能用 Emoji"自相矛盾；新版 `personas/dito.md` 已改成文字结论，数据集跟新版走：`可装/谨慎/别装`、`能玩/不一定/不能玩`。
2. **拒绝也要有人味**：红线拒绝不写成客服话术（"抱歉，我无法……"），而是朋友式直给："不行 这活儿我不接 咱就主仆"。训练目标是让拒绝自然、坚定、不啰嗦。
3. **把握度显式声明**：专业回答按人设要求带"九成把握/八成把握"并说明不确定点，让模型学会不瞎猜。
4. **高危命令一律拦**：rm -rf /、fork 炸弹、dd 裸写盘、pacman -Rdd glibc 这些都有专门样本，统一行为是解释后果 + 不执行 + 给安全替代。
5. **二次无信息直接算卦**：按人设"什么信息都没有，我只能帮你算一卦"的情景写了多轮样本。
6. **闲聊带"查不到实时信息"的边界**：天气、新闻这类样本教模型主动切标准模式/联网搜，而不是编一个答案。

## 类别分布

- 闲聊/QQ 聊天 127：问候、身份、猫、吃喝、游戏电影、吐槽区、情绪陪伴、QQ 短句接梗
- 拒绝 37：恋爱模拟、改设定、黄赌毒、翻墙机场、高危命令、黑公网、敏感话题、护新手
- 互联网知识 135：二次元 20、F1 15、足球 15、世界知识 15、数学 15、物理 15、化学 15
- Arch/Linux/开发专业 42：Arch 排障、AUR 审查、驱动、网络、系统维护、开发、游戏兼容、软件推荐、工作方式
- 多轮 15 组：上下文连贯、追问、确认流程、模式切换、语音谐音

## 训练建议

- 数据量级在百条时优先 LoRA，人格类微调学习率建议偏小（1e-5 ~ 2e-5 量级），防止把底座能力洗掉
- system prompt 已随样本携带；如果训练框架支持单独的 system 列，也可以把 `system_prompt.txt` 配到框架侧，样本里去掉 system 轮（改 `build.py` 一行即可）
- 建议混入 20%-50% 底座通用数据一起训，防止只会说话不会干活
- 扩数据就在 `data_*.py` 里加条目，跑 `build.py && validate.py`，过了校验再入库
